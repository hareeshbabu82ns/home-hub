# ImageAnimator Component

A React component that creates smooth animations by cycling through multiple images, similar to `AnimatedSvg` but for regular image files (JPG, PNG, GIF, etc.).

## Features

- **Multiple Animation Modes:**
  - Auto-play: Automatically cycles through images
  - Hover-to-play: Animation starts on hover (like AnimatedSvg)
  - Click-to-play: Toggle animation with clicks
- **Robust Error Handling:**
  - Gracefully handles image load failures
  - Filters out broken images from animation
  - Shows appropriate fallbacks

- **Performance Optimized:**
  - Preloads next few images for smooth animation
  - Uses Next.js Image component for optimization
  - Memory-efficient frame cycling

- **Visual Indicators:**
  - Animation status indicator (green = playing, yellow = paused)
  - Frame counter showing current position
  - Appropriate tooltips and accessibility

## Usage

### Basic Example

```tsx
import ImageAnimator from "@/components/ImageAnimator";

function MyComponent() {
  const images = [
    "/path/to/image1.jpg",
    "/path/to/image2.jpg",
    "/path/to/image3.jpg",
  ];

  return (
    <ImageAnimator
      images={images}
      className="h-64 w-64"
      animationDuration={2000}
      autoPlay={false}
      playOnHover={true}
      loop={true}
    />
  );
}
```

### In ExerciseCard

The component is automatically used in `ExerciseCard` when:

1. No SVG animation is available (`anim` field is empty or broken)
2. The `localImages` field contains multiple images
3. Images are sorted by their numeric suffix (`image_1`, `image_2`, etc.)

```tsx
// This logic is already implemented in ExerciseCard.tsx
const localImageUrls = getLocalImages(); // Gets sorted array from localImages field

{
  localImageUrls.length > 0 ? (
    <ImageAnimator
      images={localImageUrls}
      className="h-full w-full"
      animationDuration={2000}
      autoPlay={false}
      playOnHover={true}
      loop={true}
    />
  ) : (
    <div>No image</div>
  );
}
```

## Props

| Prop                | Type       | Default     | Description                            |
| ------------------- | ---------- | ----------- | -------------------------------------- |
| `images`            | `string[]` | Required    | Array of image URLs to animate through |
| `className`         | `string`   | `undefined` | CSS classes for styling                |
| `animationDuration` | `number`   | `2000`      | Total duration for full cycle (ms)     |
| `autoPlay`          | `boolean`  | `false`     | Start animation automatically          |
| `loop`              | `boolean`  | `true`      | Loop animation continuously            |
| `playOnHover`       | `boolean`  | `false`     | Start animation on hover               |
| `onImageChange`     | `function` | `undefined` | Callback when image changes            |

## Database Schema Integration

The component works with the `localImages` field in the Exercise schema:

```prisma
model Exercise {
  // ... other fields
  localImages Json? @map("local_images") // Format: {"image_1": "/path1.jpg", "image_2": "/path2.jpg"}
}
```

The `localImages` field structure:

- Keys: `image_1`, `image_2`, `image_3`, etc.
- Values: Relative paths to local image files
- Generated by exercise upload scripts when multiple images are available

## Integration with Exercise Cards

The `ExerciseCard` component now follows this image priority:

1. **SVG Animation** (`anim` field) - Highest priority, uses `AnimatedSvg`
2. **Static Image** (`img` field) - Single image using Next.js `Image`
3. **Local Images** (`localImages` field) - Multiple images using `ImageAnimator`
4. **No Image** - Placeholder text

This ensures the best possible visual experience for each exercise while maintaining consistent behavior.
